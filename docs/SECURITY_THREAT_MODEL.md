# Безопасность «Солидарности» — модель угроз v0.1

**Абсолютную неуязвимость гарантировать нельзя.** Цель: не доверять одному каналу, предотвращать кражу денег и приватных данных, делать изменения обнаружимыми и обратимыми.

| Угроза | Защита |
|---|---|
| Кража бот-токена | Secrets manager, ротация, ограниченные права; у бота нет банковских ключей |
| Подделка Telegram webhook | HTTPS, `X-Telegram-Bot-Api-Secret-Token`, ограничения запросов, дедупликация `update_id` |
| Подмена Telegram Mini App login | Проверка `initData` на сервере по правилам Telegram; срок годности; нет доверия клиенту |
| Утечка данных детей и получателей | Минимизация, отдельное шифрованное хранилище, RBAC, журнал доступа, юридическое основание |
| Фальшивые оплаты | Подписанные события провайдера + сверка банка; не доверять скриншотам и чату |
| Повтор платежа | Уникальные ID и идемпотентность, транзакционное резервирование суммы |
| Смена реквизитов мошенником | Повторная аутентификация, период охлаждения, независимая проверка |
| Самоплатёж администратора | Два независимых подписанта, конфликт интересов, банковские лимиты и уведомления |
| Манипуляция жеребьёвкой | Seed commitment до закрытия списка, snapshot, reveal, воспроизведение |
| Взлом приложения / зависимостей | Версионирование, подпись релизов, CI, анализ зависимостей, OWASP ASVS 5 |
| DDoS / шантаж | Rate limits, WAF, резервные копии, план восстановления, emergency stop |

Административные роли: аппаратные passkeys/FIDO2 и дополнительное подтверждение переводов; разведение полномочий при проверке, утверждении и платеже; ревизор может проверить, но не перевести. В Telegram-боте нет функции отправки денег. Токены никогда не помещаются в репозиторий.

Обязательные перед запуском: аудит OWASP ASVS 5 уровня L2 (для переводов усилить), независимый pentest, защита webhook от replay, резервное восстановление, расследование инцидентов, отчёт о конфиденциальности и законности обработки данных.

Источники: [Telegram Bot API](https://core.telegram.org/bots/api), [Telegram Bot Terms](https://telegram.org/tos/bot-developers), [OWASP ASVS 5](https://asvs.owasp.org/).


## v0.2 — фальшивые получатели и независимые выплаты

- **Поддельная личность / дубликат заявителя:** независимая идентификация через законного провайдера, проверка совпадений с минимизацией данных, ручной разбор сомнительных случаев; одна биометрия не гарантирует защиты от всех подделок.
- **Deepfake / подмена лица:** проверка живости и защита от presentation/injection атак только силами аттестованного поставщика; не собирать selfies и шаблоны в Telegram.
- **Кража телефона / вход по чужому PIN:** passkey/WebAuthn User Verification подтверждает контроль зарегистрированного аутентификатора, не паспортную личность и не обязательное использование биометрии; финансовые операции требуют отдельного identity proof и подтверждения конкретных реквизитов.
- **Подмена получателя/суммы:** согласия и approvals относятся к digest всех платёжных полей; при любых изменениях они сбрасываются. Фиксация nonce и запрет replay в серверной БД.
- **Мошенничество двух аффилированных администраторов:** разделение ролей, независимость, сверка конфликтов интересов и неизменяемый внешний аудит.
- **Отказ от биометрии / нет смартфона:** идентификация через законный очный или иной небиометрический путь, апелляция и отсутствие автоматического отказа в помощи только по этой причине.
- **Несовершеннолетние:** подтверждение личности и полномочий законного представителя; никаких биометрических данных ребёнка по умолчанию.

Демонстрационный [policy gate](../core/payout_guard.py) проверяет только структуру и взаимные ссылки доказательств, переданных доверенным серверным адаптером. Он **не выполняет** проверки подписи, ЕБС, WebAuthn, KYC, настоящей банковской привязки и резервирования баланса. Не выдавать unit-тесты за аудит защищённости.

## v0.4: предотвращение злоупотреблений при массовых взносах и крупных фондах

- **Платный «билет» под видом пожертвования:** взнос не участвует в алгоритме выбора получателей и не создаёт право на приз/лотерею.
- **Дробление заявок одного человека:** независимая идентификация в правомерном контуре и агрегированный лимит по уникальной личности за скользящие 12 месяцев; невозможно гарантировать «нулевое мошенничество», нужен независимый аудит и апелляция.
- **Микроплатёжные потери:** не обещать приём $0.01, если провайдер устанавливает минимум и комиссия съедает взнос; прозрачное раскрытие расходов, банковская сверка.
- **Большая выплата уязвимому человеку:** не публиковать имя/местонахождение/персональные суммы, оценить риски ограбления/давления, предлагать добровольно согласованные этапы и защищённые счета, сохранять автономию.
- **Обход потолка через разные валюты и страны:** единый курс от независимого источника, фиксация времени конвертации, одна валюта внутри каждого расчёта, контроль исторических выплат и законных ограничений.
- **«Фальсификация невозможна»:** не делать абсолютных заявлений. Цель — независимые проверки, аудируемость событий, стоп при конфликте и невозможность одиночного оператора тайно перевести средства.
